# 课堂抽签转盘 设计文档

日期：2026-10-13

## 1. 目标

老师在课堂上用转盘随机抽学生回答问题。学生用自己的手机，针对每道题给自己加权重（想回答）或减权重（不想回答）。老师只能看到每个学生的**累计**加分 / 减分 / 净积分，看不到任何单道题的调整情况。整个程序界面为中文。

## 2. 架构

```
老师电脑浏览器 ──┐
                 ├──► 静态前端（Vite + React + TypeScript，部署在 Netlify）
学生手机浏览器 ──┘          │
                            ▼
                Supabase（Postgres + Realtime + Auth）
```

- 不需要自建服务器。所有敏感逻辑都放在 Postgres 函数（`SECURITY DEFINER`）里。
- 老师用 Supabase Auth 邮箱 + 密码登录。
- 学生不用注册，靠"认领名字"拿到设备令牌（device token），令牌存在手机的 `localStorage` 里。

### 隐私保证

- `adjustments`（单题调整）表开启 RLS 且**没有任何 SELECT 策略**，任何客户端（包括老师）都不能直接读取。
- 该表只能通过数据库函数读写；函数只返回汇总结果（被抽中的人、已调整人数、结算后的累计值）。
- 学生统计只在"下课结算"时更新，防止老师在单题前后对比统计、推算出单题数据。

## 3. 抽签规则

- 每道题开始时，每个在场学生的权重为 **10**。
- 学生每按一次 **+** 权重加 1，每按一次 **−** 权重减 1，次数不限，最低为 **0**，没有上限。
- 题目内存储的是净调整值 `delta`（整数，`delta >= -10`），权重 = `10 + delta`。
- 抽中概率 = 自己的权重 ÷ 所有候选人权重之和。
- 候选人 = 本节课在场的学生；如果开了"本节课已抽过的人不再参与"，则排除本节课已被抽中的人。
- 如果所有候选人的权重都是 0，则在候选人中平均抽取。
- 没有候选人时，转盘按钮不可用。
- 转盘动画上每个扇区一样大，结果由数据库按权重决定，动画停在被抽中的人的扇区。

## 4. 统计规则

- 以**每道题的最终 `delta`** 为准，题目内来回按不会重复计数。
- 累计加分 = 所有已结算题目中正 `delta` 之和。
- 累计减分 = 所有已结算题目中负 `delta` 之和（显示为负数）。
- 净积分 = 累计加分 + 累计减分。
- `delta = 0` 不计入。
- 统计跨课次累计，直到老师手动清零（按班级）。

## 5. 数据模型

| 表 | 字段（主要） | 访问权限 |
|---|---|---|
| `classes` | `id`, `teacher_id`, `name`, `join_code`（短随机码，唯一）, `created_at` | 老师本人读写 |
| `students` | `id`, `class_id`, `name`, `seq`, `device_token_hash`（可空）, `total_plus`, `total_minus` | 老师本人读写（统计和设备绑定只能通过函数修改） |
| `lessons` | `id`, `class_id`, `started_at`, `settled_at`（可空）, `exclude_picked`（bool） | 老师本人读写 |
| `attendance` | `lesson_id`, `student_id` | 老师本人读写；学生加入时由函数写入 |
| `questions` | `id`, `lesson_id`, `status`（`open` / `spun`）, `winner_student_id`, `created_at` | 公开可读（用于 Realtime 推送），只能通过函数写 |
| `adjustments` | `question_id`, `student_id`, `delta` | **无任何直接读取权限** |

设备令牌只存哈希（`device_token_hash`），明文只在学生手机上。

## 6. 数据库函数（RPC）

学生端（匿名调用）：

- `get_class_public(join_code)` → 班级名、学生名单（id、名字、是否已被认领）。
- `claim_student(join_code, student_id)` → 返回新的设备令牌；名字已被认领则报错。同时把该学生记入当前课次的出勤。
- `student_state(token)` → 自己的名字、当前题目状态、自己本题的 `delta`、被抽中者的名字（已转时）。如果该班有进行中的课次，同时把该学生记入出勤（已认领过的学生下节课打开页面即算在场）。

"当前课次"指该班级最新一个 `settled_at` 为空的课次；"当前题目"指当前课次中最新的一道题。
- `adjust(token, question_id, step)`：`step` 为 `+1` 或 `-1`；题目不是 `open` 则报错；`delta` 不低于 −10。返回新的 `delta`。

老师端（需登录且是该班级的老师）：

- `start_lesson(class_id, exclude_picked)` → 新课次。如果该班有未结算的课次，前端提示先结算。
- `start_question(lesson_id)` → 新题目（`open`）。同一课次同时只能有一道 `open` 的题。
- `adjusted_count(question_id)` → 本题 `delta != 0` 的人数。
- `spin(question_id)` → 按第 3 节规则抽人，把题目改为 `spun`，写入 `winner_student_id`，返回被抽中者 id 和名字。题目不是 `open` 则报错。
- `settle_lesson(lesson_id)` → 把本课次已转题目的 `delta` 累加进学生的 `total_plus` / `total_minus`，取消未转的题，删除本课次的 `adjustments`，写入 `settled_at`。已结算过则不做任何事（幂等）。
- `release_student(student_id)` → 清空设备绑定。
- `reset_stats(class_id)` → 清零该班统计。

## 7. 页面

### 老师端（电脑，适合投屏）

1. **登录页**：邮箱 + 密码。
2. **班级列表**：新建班级；粘贴名单（一行一个名字）；增删学生；解绑学生设备；清零统计。
3. **上课页**：
   - 大转盘（扇区等大，显示候选人名字）。
   - 班级二维码 + 链接（`/join/<join_code>`）。
   - "开始新题"按钮 → 显示"已调整 X / Y 人"（轮询 `adjusted_count`，每 2 秒）。
   - "转！"按钮 → 调用 `spin`，转盘动画停在被抽中者，大字显示名字。
   - "本节课已抽过的人不再参与"勾选项。
   - 在场名单：学生加入后自动在场；老师可手动勾选 / 取消。
   - "下课结算"按钮。
4. **统计页**：每个学生的累计加分、累计减分、净积分，可按列排序。

### 学生端（手机）

1. 扫码打开 `/join/<join_code>` → 点自己的名字 → 手机记住令牌。已有令牌则直接进入。
2. 等待页："等待老师出题…"
3. 出题后：`[ − ]  权重  [ + ]` 调整器，显示当前权重（从 10 开始）。
4. 转完后："被抽中的是：XXX"；抽中自己时醒目提示。

学生端通过 Supabase Realtime 订阅 `questions` 表的变化；断线重连后调用 `student_state` 拉取最新状态。

## 8. 边界情况

- 学生在转盘前没调整：`delta = 0`，权重 10。
- 学生中途加入：可以参与当前题。
- 学生选错名字 / 换手机 / 清了浏览器数据：老师解绑后重新认领。
- 老师忘了结算：开始新课次时提示有未结算课次，可一键结算。
- 同一课次已有 `open` 的题时再点"开始新题"：前端禁用按钮。

## 9. 测试

- **数据库（pgTAP，`supabase test db`）**：
  - 匿名用户和老师都无法 `select` `adjustments`。
  - 其他老师无法调用本班的老师端函数。
  - `adjust` 不允许 `delta < -10`，不允许对 `spun` 题目调整。
  - `spin` 的候选人过滤（在场、排除已抽过）、全零权重时平均抽取。
  - `settle_lesson` 幂等。
- **前端（Vitest）**：转盘最终角度计算（给定候选人列表和被抽中者，指针落在正确扇区）。
- **手动检查**：手机尺寸下的学生端页面，老师端投屏效果。

## 10. 不做的事（YAGNI）

- 学生口令 / 账号。
- 多位老师共管一个班。
- 按题目查看历史记录。
- 导出 Excel（以后需要再加）。
